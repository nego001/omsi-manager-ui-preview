# M98 — concurrent cooperating multi-file fixture attempts

Test-only wrapper around M97 and existing exclusive-create fixture reservation. Validated actor and checkpoint, marker-checked temporary root; acquire reservation before entering publication. Two concurrent child processes yield one winner and one busy refusal; a third contender while the winner is paused and a retry after forced termination must leave all fixture bytes unchanged. A malformed preexisting reservation is not reclaimed, independent roots progress independently. Three tests. A reservation is NOT a native OS lock, owner-liveness evidence, adversarial exclusion, persistent authorization or a production transaction lock. The legacy M97 worker does not participate in this experimental protocol, so exclusion applies only to cooperating M98 workers. No automatic removal/reclaim, real mod access, IPC integration or release. M99: explicit operation-lock protocol and stale-reservation review. Strict Ubuntu24 gate mandatory.
